1. Installation

The template is static HTML. There is no build step and no package to install.

  1. Unzip the package and open pages/index.html in a browser.
  2. For a realistic test (fonts, localStorage, file uploads), serve the folder locally: python3 -m http.server or npx serve ., then visit http://localhost:8000/pages/.
  3. Upload the whole folder to any static host (Netlify, Vercel, GitHub Pages, Cloudflare Pages, cPanel). The root index.html redirects to pages/index.html; if your host allows it, set pages/ as the site root instead and adjust asset paths.
  4. Search the project for TODO. Every customisation point is marked: domain, form endpoints, map, booking calendar, payments, product data.
  5. Replace https://www.inkmark.example with your domain in all pages, sitemap.xml and robots.txt.
Bootstrap is loaded from jsDelivr with Subresource Integrity hashes for v5.3.3. If you change the version, update or remove the integrity attributes, otherwise the browser will block the file.

Shared header and footer

Header, footer, quote drawer, toast and live region are identical on every page and marked with <!-- ============ HEADER (shared) ============ --> comments. If you edit them, apply the same change to every page (a find-and-replace across pages/*.html works well), or move them into includes if your host supports them.

The current page is marked with aria-current="page" on its nav link; keep that attribute when editing.

3. Colours & dark mode

Brand colours live at the top of style.css. Change them once and every component follows:

:root {
  --ink-800:   #1B2A4A;  /* primary: deep ink navy */
  --red-700:   #A8231D;  /* secondary: stamp red */
  --brass-700: #8C6A2A;  /* accent: brass (text-safe on paper) */
  --paper-100: #F3EEE2;  /* page background */
  --charcoal-700: #26262B;
}

Components use semantic tokens (--c-bg, --c-surface, --c-text, --c-primary, --c-secondary, --c-accent, --c-border…). dark-mode.css redefines only those tokens under [data-theme="dark"]. When you change a brand colour, check both palettes still reach 4.5:1 contrast for text (WebAIM's contrast checker is quick).

The theme follows the visitor's system preference until they use the toggle; the choice is saved as inkmark-theme in localStorage. An inline script in each <head> applies it before paint, so there is no flash.

Stamp proofs (preview canvas, gallery samples, upload preview) intentionally stay on light paper in dark mode: a proof is always shown on paper.

4. Fonts & type

Three Google Fonts: Young Serif (headings), Public Sans (body) and Courier Prime (workshop-ticket labels for codes, sizes and specs). To change them, edit the Google Fonts <link> in each page head and the variables:

--f-head: "Young Serif", Georgia, serif;
--f-body: "Public Sans", system-ui, sans-serif;
--f-mono: "Courier Prime", "Courier New", monospace;

To self-host (better privacy and speed), download WOFF2 files into assets/fonts/, add @font-face rules at the top of style.css with font-display: swap, and remove the Google Fonts links. The type scale (--fs-*) uses a 1.25 ratio with fluid clamp() for H1 and H2.

5. Content & images

  • Brand name: search for InkMark and Seal Co.. The logo mark is two image files: logo-mark.webp (for light backgrounds) and logo-mark-light.webp (footer and dark mode). Replace both at 120 × 120 px; the header swaps them automatically with the theme. Replace favicon-32.png and apple-touch-icon.png (180 × 180) too.
  • Products: edit assets/js/plugins/catalog.js. Each item needs id, name, category, code, size, price, blurb, image, alt. Categories: self-inking, logo, notary, date, accessories. Product links use product-details.html?id=….
  • Images: every image is a WebP file (products 800 × 800 with transparent background, hero, gallery samples, seals and avatars at 2× resolution). Replace them with real photos at the same aspect ratios (products 1:1, about 4:3, team 1:1, blog 16:10), keep width/height attributes to prevent layout shift, keep loading="lazy" below the fold and write a specific alt. Don't reuse the same image in two sections.
  • Stamp sizes and prices in the preview: edit SIZES and INKS in stamp-preview.js.
  • Contact details and hours appear in the footer, contact page and the JSON-LD block in every head.

Breakpoints

Custom CSS uses the brief's breakpoints: below 640px, 640–1024px, 1024–1280px and above 1280px. Bootstrap's grid keeps its own (576/768/992/1200/1400); the main navigation collapses below 1200px. To make Bootstrap's grid match exactly, recompile Bootstrap from Sass with custom $grid-breakpoints.

7. JavaScript plugins

All scripts are vanilla ES6+, loaded with defer, and only run when their markup is present.

Live stamp preview — plugins/stamp-preview.js

Hook: <section data-stamp-builder> containing inputs named sp-line1/2/3, sp-shape, sp-size, sp-ink, sp-font, sp-double, sp-worn, plus [data-stamp-output], [data-stamp-size], [data-stamp-price] and [data-stamp-summary]. Multiple builders per page are supported. User text is inserted with textContent only. The preview is drawn live in the browser (it can't be a static image); the download button exports it as a 1200 px PNG.

Design upload — plugins/upload.js

Hook: [data-dropzone] with data-list and data-preview selectors. Edit ACCEPT, MAX_MB (10) and MAX_FILES (5). Valid files are written back into the file input, so a normal multipart/form-data POST sends them.

Quote list — in main.js

Any button with data-quote-add data-name="…" data-meta="…" adds an item. With data-quote-form="#form", values of fields marked data-quote-field are collected. Items are stored as inkmark-quote in localStorage and pre-fill the contact form when visitors click "Send quote request".

Form validation — in main.js

Add data-validate to any form. Native constraints (required, type, minlength, pattern) are checked and shown inline. Custom messages: data-msg-required, data-msg-type, data-msg-pattern, data-msg-short; matching fields: data-match="#otherId". data-demo prevents real submission and shows data-success; remove it once the form has a real endpoint.

8. Forms & integrations

  • Formspree: set action="https://formspree.io/f/YOUR_ID" (already in place) and remove data-demo. File uploads need a paid Formspree plan.
  • Netlify Forms: add data-netlify="true" and a name to the form, remove action and data-demo.
  • Mailchimp: paste your list URL (…list-manage.com/subscribe/post?u=…&id=…) into the newsletter form action; the email field is already named EMAIL.
  • ConvertKit: action="https://app.convertkit.com/forms/FORM_ID/subscriptions" and rename the field to email_address.
  • Google Maps: replace .map-placeholder on the contact page with the commented <iframe>; keep the title attribute.
  • Booking calendar: embed Calendly or Cal.com inside #booking-calendar on service-details.html.
  • Stripe / PayPal: mount Stripe Checkout or PayPal Smart Buttons in #payment-buttons on product-details.html. Payment icons are in the footer.

9. RTL (Arabic, Hebrew)

  1. Set <html lang="ar" dir="rtl"> (or he).
  2. Swap bootstrap.min.css for bootstrap.rtl.min.css and update its integrity hash.
  3. rtl.css is already loaded after style.css. Layout uses logical properties (inset-inline, margin-inline, padding-inline), so most components flip automatically.

The RTL button in the header (next to the theme toggle) and the "RTL preview" button in the footer both toggle direction for testing and remember it. Remove the buttons ([data-dir-toggle]) for production.

10. Accessibility & performance

  • Skip link, one H1 per page, logical heading order, landmarks and labelled navigation.
  • Visible focus ring (--c-focus), 44px minimum touch targets, keyboard-operable menus, tabs, accordions, modals and the stamp builder.
  • Inline errors are linked with aria-describedby and aria-invalid; status messages and the stamp preview summary use live regions.
  • prefers-reduced-motion disables the hero press, reveals and shimmer.
  • Performance: no framework, deferred scripts, WebP images with width/height set and lazy loading, fetchpriority="high" on each page's main image, preconnect to font hosts. For PageSpeed 90+ in production, self-host fonts, enable compression and long cache headers, and keep replacement photos under ~150 KB.

11. SEO

Every page has a unique title (≤ 60 characters), meta description (150–160 characters), canonical URL and Open Graph tags. JSON-LD: Store (LocalBusiness) on all pages, Product on product details, FAQPage on both homes and service details, BlogPosting on the article. Utility and login pages are noindex and disallowed in robots.txt. Update sitemap.xml when you add pages.
